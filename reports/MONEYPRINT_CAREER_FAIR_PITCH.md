# 60–90-Second Recruiter Pitch

I built MONEYPRINT as a transaction-risk analytics portfolio project using PaySim, a synthetic mobile-money dataset with about 6.36 million transactions. I used Python and DuckDB to audit balances and explore transaction patterns, then created an explainable logistic-regression ranking model that prioritizes CASH_OUT and TRANSFER cases under fixed investigation budgets. To test stability, I used four expanding chronological validation folds instead of randomly splitting transactions, and kept the previously examined later period clearly labeled exploratory. The selected model uses transaction amount and type, simulated hour, and sender pre-transaction balance features. Those balance features produce a large lift, which is also a warning: PaySim’s simulator may make the task artificially easy. I built a three-page Power BI report covering population patterns, saved risk-ranked cases, and model reliability. Selecting a case reveals its saved context, while investigation-budget controls compare precision and recall. At top 500, the exploratory later-period queue contains 456 retrospective fraud labels, with 91.2% precision and 36.42% recall. I keep those selected-case results separate from population prevalence. This is a synthetic research demonstration, not a real bKash deployment or claim of production fraud detection.
